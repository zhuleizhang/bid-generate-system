## Codebase Patterns
- FastAPI 后端使用 Pydantic BaseSettings + lru_cache 管理配置，所有环境变量通过 get_settings() 读取
- 后端项目结构：app/api/ (路由)、app/core/ (配置)、app/models/ (数据模型)、app/services/ (业务逻辑)、app/gateway/ (外部网关)
- Docker 使用 python:3.12-slim 基础镜像，构建时需安装 gcc/libxml2-dev/libxslt-dev 以编译 lxml
- .gitignore 已涵盖 Python/Node.js 常见忽略项（venv、__pycache__、node_modules、.env、.mypy_cache）
- 前端使用 Next.js 16 App Router + Ant Design + @ant-design/nextjs-registry，布局采用 Ant Design Layout 组件（Sider + Header + Content）
- 前端 typecheck 使用 `npx tsc --noEmit`，lint 使用 `npx eslint`（Next.js 16 中 lint 脚本改为了直接调用 eslint）
- Node 版本要求 >= 20.9.0（Next.js 16 要求），使用 nvm use v20.19.5 切换
- Supabase migration 文件格式：YYYYMMDDHHMMSS_description.sql，放在 supabase/migrations/ 目录
- 数据库 Schema 使用 CHECK 约束枚举值（如 document_type IN ('bid_template', 'tender_doc', ...)），不使用 ENUM 类型
- 所有表的 updated_at 通过统一的 trigger_set_updated_at() 触发器自动维护，不依赖 ORM
- JSONB 字段用于灵活扩展（metadata、related_requirement_ids），默认值使用 '[]' 或 '{}'
- DOCX 文件本质是 ZIP 压缩包，使用 Python 标准库 zipfile 解包即可提取 word/document.xml、styles.xml、页眉页脚等 XML 部件
- Supabase Storage 文件上传需在 upload() 的第三个参数中指定 content-type，否则默认 application/octet-stream
- DOCX 解析使用 lxml + WordprocessingML 命名空间（http://schemas.openxmlformats.org/wordprocessingml/2006/main），所有标签查询需带命名空间前缀
- 文档结构树的父子关系使用 _temp_id/_temp_parent_id 临时 ID 机制：解析时分配临时 ID，数据库插入后通过 order_index 排序对齐，再映射回填真实 parent_node_id
- Supabase Storage 公开 URL 格式为 {SUPABASE_URL}/storage/v1/object/public/{bucket}/{path}，通过公开 URL 下载需用 httpx 而非 Storage API
- 表格解析采用两遍扫描法：第一遍收集所有单元格信息并构建网格，处理合并关系；第二遍才创建节点（跳过 vMerge continue 单元格）
- DOCX vMerge 的 val 属性可能缺失（部分工具生成），需根据同列上方是否已有 restart 来推断当前单元格是否为 continue
